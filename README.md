# Oxygen GTK

A GTK 2/3/4 theme that gives GTK applications the look of KDE's **Oxygen**
style, while still being generated from, and following, the active KDE colour
scheme.

It is derived from [Breeze GTK](https://invent.kde.org/plasma/breeze-gtk)
(GTK2 pixmaps originally by
[scionicspectre](https://github.com/scionicspectre/BreezyGTK)). The Breeze
build system, colour-scheme plumbing, named-colour API and widget structure are
kept; the visual layer follows Oxygen.

| | |
|---|---|
| Theme name | `Oxygen` (a single theme; `gtk-dark.css` is the dark fallback) |
| Project / package id | `oxygen-gtk-theme` |

## What looks like Oxygen

* Lit gradients, dark outlines with a light inner bevel, inset fields and
  coloured hover/focus glows on buttons, entries, tabs, toolbars, titlebars,
  tooltips, selections, scrollbars, sliders, switches and progress bars.
* **Window controls** built like the buttons of the Oxygen window decoration
  (`DecoHelper::windecoButton`, `Button::paint`): a 21px button with a glossy
  disc (light top to dark bottom), a light-to-mid outline, a soft shadow, and on
  hover a halo plus glyph in the scheme's hover colour (its negative/red colour
  for close). The glyphs (minimise `v`, maximise `^`, restore diamond, close
  `x`) use the decoration's own 21 unit geometry with its light emboss copy.
  Everything is a fixed-size background image made of opaque shapes (gradients
  are nine bands of colour, the shadow and halo are mixed with the title bar
  colour), so the controls keep their shape where GTK4 stretches the buttons and
  draw the same in any SVG renderer. In an inactive window they fade out.
* **Header bar**: Oxygen's title bar background, confined to the header bar. It
  starts at a slightly lighter top colour and relaxes to the window colour at
  the bottom edge, so it joins the flat window body without a seam, with
  Oxygen's soft radial sheen at the top centre. The caption has Oxygen's light
  contrast copy below it.
* **Icons**: the check mark, radio dot and every arrow (combo boxes, spin
  buttons, tabs, menus, expanders, tree views, header bars) are bundled
  Oxygen-style glyphs, taken from the style's own check, radio and arrow
  geometry, instead of being looked up in the icon theme. They therefore look
  the same whatever icon theme is active, and nothing is missing when the
  Oxygen icon theme (which ships no `*-symbolic` arrows) is selected. The theme
  also defaults `gtk-icon-theme-name` to `oxygen`; an icon theme chosen by the
  user (for example through Plasma) overrides it.
* **Active window glow**: client-side decorated windows get Oxygen's accent
  glow (a tight bright halo plus a wide soft one, from the scheme's selection
  colour, just like Plasma's accent colour) inside a dark hairline frame.
  Inactive windows get the plain dark shadow instead.

Every gradient, outline and glow is expressed with GTK colour functions on the
exported named colours, so nothing is tied to one palette.

Windows that are decorated by the window manager (for example by KWin with the
Oxygen decoration) get their frame and glow from that decoration; the glow
drawn here appears on client-side decorated windows.

The glyph SVGs in `src/assets` are generated by `tools/generate_glyphs.py`.

## Following the system colour scheme

* The theme is generated from a KDE colour scheme. By default
  (`build_theme.sh` with no `-c`) it uses `~/.config/kdeglobals`.
* All colours are exported as named colours with the `_breeze` suffix. That
  suffix is deliberately **not** renamed: kde-gtk-config's runtime
  `colors.css`/`gtk.css` overrides colours by those exact names, which is how
  the theme follows the Plasma colour scheme live.
* `settings.ini` loads `colorreload-gtk-module` (from kde-gtk-config).
* The standard GTK named colours (`theme_bg_color`, ...) are exported too.
* `gtk-3.0/gtk-dark.css` and `gtk-4.0/gtk-dark.css` are a full dark build, used
  by applications that ask for a dark theme outside a colour-scheme-aware
  environment.

## Build and install

Requirements: CMake, Extra CMake Modules, the Breeze package (for its stock
colour schemes), Python 3 with pycairo, and `sassc` (or Dart Sass).

```sh
cmake -B build -DCMAKE_INSTALL_PREFIX=/usr
cmake --build build
sudo cmake --install build        # installs Oxygen to share/themes
```

The light build uses the `Oxygen` colour scheme if Plasma provides it (otherwise
`BreezeLight`); the dark fallback uses `BreezeDark`. Override with
`-DOXYGEN_GTK_LIGHT_SCHEME=...` / `-DOXYGEN_GTK_DARK_SCHEME=...`.

To generate the theme from your current Plasma colours into
`~/.local/share/themes/Oxygen`:

```sh
cd src && ../build/src/build_theme.sh              # uses ~/.config/kdeglobals
cd src && ../build/src/build_theme.sh -c Oxygen    # or name a scheme
```

## How the widget look was derived

The widgets follow the Oxygen style's own drawing code
(`kstyle/oxygenstylehelper.cpp`, `kstyle/oxygenstyle.cpp`,
`liboxygen/oxygenhelper.cpp`), not Breeze:

* **Colours.** Oxygen derives *light*, *dark*, *shadow* and *mid* colours from a
  surface colour with `KColorScheme::shade()` in HCY space. `tools/oxygen_colors.py`
  ports that, and the GTK expressions `oxy-light`, `oxy-dark`, `oxy-shadow` and
  `oxy-mid` in `src/_oxygen.scss` are fitted to it for both light and dark
  surfaces.
* **Slabs** (buttons, check boxes, radio buttons, slider handles, tabs): no dark
  outline. A soft shadow hugs the shape, a light bevel runs round the top edge,
  and the face is a gradient from 79% light colour at the top to the plain colour
  at 76% of the height. Hover and focus add a 3px halo in the hover / focus
  colour; pressed and checked slabs are sunken (inner shadow, flipped gradient,
  bright line below).
* **Holes** (text fields, slider / scroll bar / progress grooves): an inner
  shadow along the top, an outline that darkens towards the bottom, and a bright
  contrast line just below. Grooves are filled with the dark colour. Focus draws
  the glow along the inside of the hole.
* **Scroll bars**: a 15px dark groove holding a raised, glossy 9px handle.
  Overlay scroll bars keep the thin layout.
* **Sliders** have a dark groove and a round raised handle but no filled part,
  as in Qt. **Progress bars** use the highlight colour mixed 20% with the dark
  colour, a sheen at the top and bottom, and a light-to-dark bevel.
* **Tabs and frames**: the page frame is a slab edge with no fill; the selected
  tab shares it and gets a fading light sheen, unselected tabs are flat, darker
  and translucent. Tree view headers are flat with an etched dark/light line.
* **Selection** is a gradient from 130% of the highlight colour to the highlight
  colour.

## Scroll bars

Oxygen has no overlay scroll bars, so the theme asks GTK for permanent ones: the
build writes `gtk-3.0/settings.ini` and `gtk-4.0/settings.ini` (GTK reads a
`settings.ini` next to a theme's `gtk.css` as that theme's default settings)
containing `gtk-overlay-scrolling=false`. Some settings sources outrank a theme's
defaults, so if you still get overlay scroll bars, set it yourself:

* `gsettings set org.gnome.desktop.interface overlay-scrolling false`
* or `gtk-overlay-scrolling=false` under `[Settings]` in
  `~/.config/gtk-3.0/settings.ini` and `~/.config/gtk-4.0/settings.ini`
* GTK3 also honours `GTK_OVERLAY_SCROLLING=0` in the environment (GTK4 does not)

Applications that explicitly request overlay scrolling still get it; their bars
expand into the Oxygen scroll bar while hovered or dragged.

## GTK 2

The GTK2 theme is a set of generated pixmaps (`gtk-2.0/gtkrc`, loaded through
GTK2's `pixmap` engine, which ships with GTK2).

If a GTK2 application shows the stock look instead:

* GTK2 does not search `~/.local/share/themes`. It looks in `~/.themes` and in
  `$GTK_DATA_PREFIX/share/themes` only, so a per-user install is invisible to
  it. Install system-wide (for example through a package or NixOS), or test
  without installing:
  `GTK2_RC_FILES=/path/to/Oxygen/gtk-2.0/gtkrc gtk-demo`
* Watch the terminal output: GTK2 prints `Unable to locate theme engine in
  module_path` when a theme names an engine that is not installed, and it then
  abandons the rest of the theme. Earlier versions of this theme (and Breeze GTK)
  named the separate `adwaita` engine in one style; that dependency has been
  removed.
